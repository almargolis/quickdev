## Application: Multi-User Todo

### Data Model (pdict)

The application's core is two pdict table definitions in a single module (`todo/data_spec.py` or similar):

```python
from qdbase import pdict

db_dict = pdict.DbDictDb()

# --- people table ---
people = db_dict.add_table(pdict.DbDictTable("people"))
people.add_column(pdict.Text("name",
    is_create_required=True,
    max_length=100,
    rest_label="Full Name"))
people.add_column(pdict.Text("email",
    is_create_required=True,
    max_length=200,
    is_unique=True,
    rest_label="Email Address"))
people.add_column(pdict.Text("role",
    default_value="member",
    choices=["admin", "member"],
    rest_label="Role"))
people.add_index("idx_people_email", column_names="email", is_unique=True)

# --- tasks table ---
tasks = db_dict.add_table(pdict.DbDictTable("tasks"))
tasks.add_column(pdict.Text("title",
    is_create_required=True,
    max_length=200,
    rest_label="Task Title"))
tasks.add_column(pdict.Text("description",
    max_length=2000,
    form_widget="textarea",
    rest_label="Description"))
tasks.add_column(pdict.Text("status",
    default_value="todo",
    choices=["todo", "in_progress", "done"],
    is_filterable=True,
    rest_label="Status"))
tasks.add_column(pdict.Text("priority",
    default_value="medium",
    choices=["low", "medium", "high"],
    is_filterable=True,
    is_sortable=True,
    rest_label="Priority"))
tasks.add_column(pdict.Number("assigned_to",
    foreign_key=pdict.ForeignKey(people.columns["id"]),
    allow_nulls=True,
    is_filterable=True,
    rest_label="Assigned To"))
tasks.add_column(pdict.TimeStamp("due_date",
    allow_nulls=True,
    is_sortable=True,
    rest_label="Due Date"))
tasks.add_column(pdict.TimeStamp("created_at",
    is_read_only=True,
    is_sortable=True,
    rest_label="Created"))
```

### What qdflask-repo should provide from this

With the pdict definitions above and minimal glue code:

| Layer | Package | What it generates |
|-------|---------|-------------------|
| **REST API** | qdrestful | CRUD endpoints for `/restful/people` and `/restful/tasks` with filtering, sorting, pagination |
| **Web Forms** | qdforms | List views and add/edit forms for both tables, with FK popup for `assigned_to` |
| **MCP Server** | qdrestful | MCP tool definitions so AI agents can read/write people and tasks |
| **Auth** | qdflask + qdflaskauth | User login, role-based access to API and forms |
| **API Keys** | qdflaskapi | Bearer token access for programmatic clients |

### Glue code needed

The glue code should be minimal — ideally just:

1. **`data_spec.py`** — The pdict definitions above
2. **`app.py`** (or auto-generated by qdstart) — Flask app factory that:
   - Imports `db_dict` from `data_spec`
   - Sets `app.config['QDRESTFUL_DB_DICT'] = db_dict`
   - Calls `init_*` functions in priority order
3. **`qd_conf.toml`** — Package configuration (may be auto-generated by qdsetup)
4. **`bootstrap.toml` / `qdboot_answers.toml`** — Installation answers for qdboot

## Tracking Issues

As we work through each phase, issues will be logged here with the format:

```
### Issue: [short description]
- **Found in**: Phase N
- **Repo**: quickdev | qdflask-repo
- **File(s)**: path/to/file
- **Description**: what's wrong
- **Resolution**: what was changed
```

### Issue 1: ai_skills.md uses wrong parameter names for pdict Column
- **Found in**: Phase 1
- **Repo**: quickdev (ai_skills.md, qdbase/ai_skills.md) and qdflask-repo (ai_skills.md)
- **File(s)**: `quickdev/ai_skills.md`, `quickdev/qdbase/ai_skills.md`, `qdflask-repo/ai_skills.md`
- **Description**: The ai_skills files document `nullable` and `unique` as Column options. The actual pdict API uses `allow_nulls` and `is_unique`. An AI following the docs would produce code that silently ignores the kwargs (they fall into `**argv` but have no effect since they don't match any slot name).
- **Resolution**: Update all ai_skills.md files to use `allow_nulls` and `is_unique`.

### Issue 2: ai_skills.md doesn't document ColumnName for SQL expression defaults
- **Found in**: Phase 1
- **Repo**: quickdev
- **File(s)**: `quickdev/ai_skills.md`, `quickdev/qdbase/ai_skills.md`
- **Description**: `pdict.ColumnName("CURRENT_TIMESTAMP")` is the mechanism for SQL expression defaults (rendered unquoted in DDL). This is essential for timestamp columns but not mentioned in any ai_skills documentation. A developer or AI would not know how to set a `created_at` default without reading the source.
- **Resolution**: Add ColumnName to the pdict documentation in ai_skills.md files.

### Issue 3: qdsqlite does not enable PRAGMA foreign_keys
- **Found in**: Phase 1
- **Repo**: quickdev
- **File(s)**: `qdbase/src/qdbase/qdsqlite.py` (and qdbasedb.py)
- **Description**: pdict supports defining foreign keys and they appear in the generated DDL, but qdsqlite never executes `PRAGMA foreign_keys=ON`. This means FK constraints are declared but not enforced at runtime. Inserts with invalid FK references succeed silently.
- **Resolution**: Added `foreign_keys=True` parameter to `QdSqlite.__init__()`. Defaults to ON. Developers can pass `foreign_keys=False` for legacy databases or bulk imports. All existing tests pass.

### Issue 4: pdict.defaults() returns ColumnName objects as values
- **Found in**: Phase 2
- **Repo**: quickdev
- **File(s)**: `qdbase/src/qdbase/pdict.py`
- **Description**: `DbDictTable.defaults()` returned `ColumnName("CURRENT_TIMESTAMP")` objects. When qdrestful used these as insert values, sqlite3 raised `ProgrammingError: type 'ColumnName' is not supported`. ColumnName defaults are SQL expressions meant for DDL, not application-level Python values.
- **Resolution**: `defaults()` now skips columns whose `default_value` is a `ColumnName` instance.

### Issue 5: qdrestful create/update routes don't catch IntegrityError
- **Found in**: Phase 2
- **Repo**: qdflask-repo
- **File(s)**: `qdrestful/src/qdrestful/routes.py`
- **Description**: POST, PUT, and PATCH routes did not catch `IntegrityError` from qdsqlite. FK violations and unique constraint violations crashed with raw exceptions instead of returning JSON error responses.
- **Resolution**: Wrapped `db.insert()` and `db.update()` calls in `try/except db.IntegrityError`, returning `bad_request()` with the constraint error message.

### Issue 6: qdrestful applies defaults to read-only columns
- **Found in**: Phase 2
- **Repo**: qdflask-repo
- **File(s)**: `qdrestful/src/qdrestful/routes.py`
- **Description**: The create handler applied `td.defaults()` to all non-PK columns, including `is_read_only` columns. Combined with Issue 4, this caused `created_at` (read-only with a ColumnName default) to be included in inserts.
- **Resolution**: The defaults loop now skips columns where `col.is_read_only` is True.

### Issue 7: _column_to_schema crashes on ColumnName default values
- **Found in**: Phase 2
- **Repo**: qdflask-repo
- **File(s)**: `qdrestful/src/qdrestful/routes.py`
- **Description**: The `_column_to_schema()` function put `col.default_value` directly into the JSON response. For `ColumnName` objects, `jsonify()` would fail since the object is not JSON-serializable.
- **Resolution**: `_column_to_schema()` now checks for `ColumnName` instances and uses `.name` (the string expression) instead.

### Issue 8: init_qdrestful doesn't store URL prefix for qdforms
- **Found in**: Phase 3
- **Repo**: qdflask-repo
- **File(s)**: `qdrestful/src/qdrestful/__init__.py`
- **Description**: `init_qdrestful()` never set `app.config['QDRESTFUL_URL_PREFIX']`, but `init_qdforms()` reads it (defaulting to `/restful`). If the app uses a different prefix (e.g., `/api`), qdforms generates wrong API URLs in its JavaScript.
- **Resolution**: Added `app.config['QDRESTFUL_URL_PREFIX'] = url_prefix` to `init_qdrestful()`.

### Issue 9: qdforms _col_meta crashes on ColumnName default values
- **Found in**: Phase 3
- **Repo**: qdflask-repo
- **File(s)**: `qdforms/src/qdforms/routes.py`
- **Description**: The `_col_meta()` function passed `col.default_value` directly into template context. Templates use `{{ columns | tojson }}`, which fails for `ColumnName` objects (not JSON-serializable).
- **Resolution**: `_col_meta()` now converts `ColumnName` objects to their `.name` string.

### Issue 10: create_admin_user doesn't grant can_generate_api_keys
- **Found in**: Phase 4
- **Repo**: qdflask-repo
- **File(s)**: `qdflaskauth/src/qdflaskauth/__init__.py`
- **Description**: `create_admin_user()` creates the bootstrap admin with `can_generate_api_keys=False` (the column default). This means the admin who bootstraps the system cannot generate API keys without first editing their own user record through the UI — a chicken-and-egg problem for new installations.
- **Resolution**: `create_admin_user()` now sets `can_generate_api_keys=True` on the admin user for both create and update paths.

### Issue 11: MCP create handler includes ColumnName defaults and read-only columns
- **Found in**: Phase 5
- **Repo**: qdflask-repo
- **File(s)**: `qdrestful/src/qdrestful/mcp_server.py`
- **Description**: The MCP `handle_tool_call` create action did not skip read-only columns or ColumnName default values. For `created_at` (read-only, default `ColumnName("CURRENT_TIMESTAMP")`), the handler tried to insert the ColumnName object as a bind parameter, causing `ProgrammingError`. This is the same class of bug as Issues 4/6 in the REST routes.
- **Resolution**: Create handler now skips `is_read_only` columns and `ColumnName` default values. Also added `IntegrityError` handling for FK/unique violations on create and update.

### Issue 12: MCP _row_to_dict doesn't serialize datetime objects
- **Found in**: Phase 5
- **Repo**: qdflask-repo
- **File(s)**: `qdrestful/src/qdrestful/mcp_server.py`
- **Description**: `_row_to_dict()` passed raw `datetime` objects from SQLite into the response dict. The MCP server uses `json.dumps()` (not Flask's `jsonify`), which cannot serialize datetime objects, causing `TypeError: Object of type datetime is not JSON serializable`.
- **Resolution**: `_row_to_dict()` now converts `datetime` and `date` objects to ISO format strings.

### Issue 13: MCP _describe_table and _column_description don't handle ColumnName
- **Found in**: Phase 5
- **Repo**: qdflask-repo
- **File(s)**: `qdrestful/src/qdrestful/mcp_server.py`
- **Description**: `_describe_table()` and `_column_description()` passed `col.default_value` directly as `str()` or in f-strings, producing unhelpful object representations for ColumnName values.
- **Resolution**: Both functions now check for `ColumnName` instances and use `.name` (the SQL expression string).

### Issue 14: `<site_dpath>` placeholder never resolved
- **Found in**: Phase 6
- **Repo**: quickdev
- **File(s)**: `qdutils/src/qdutils/qdstart.py`, `qdbase/src/qdbase/exenv.py`
- **Description**: Answer values containing `<site_dpath>` (e.g., `<site_dpath>/conf/db/todo_data.db`) were written literally to conf files and the generated `qd_create_app.py`. The `site_dpath` key was never added to the answer cache, so `expand_answer_refs()` could not resolve it. Additionally, `exenv.write_site_config()` stored only the directory name instead of the full path.
- **Resolution**: (1) Added `repo_scanner.answer_cache['site_dpath'] = self.qdsite_dpath` before process_questions in both `QdStart.__init__` and `plan_site`. (2) Changed `_expand_conf_refs` to also call `repo_scanner.update_answer()` after expanding, so the database answers used by FlaskAppGenerator are also resolved. (3) Fixed `exenv.write_site_config()` to store `qdsite_dpath` (full path) instead of `qdsite_dname`.

### Issue 15: FlaskAppGenerator doesn't handle `source = "answers"` params
- **Found in**: Phase 6
- **Repo**: quickdev
- **File(s)**: `qdcore/src/qdcore/flaskapp.py`
- **Description**: The `_resolve_param()` method only handled `source = "answer"` (singular key) but qdrestful, qdforms, and qdflaskapi declare `source = "answers"` (plural, with a `keys` array). These packages got `config=None` in the generated code, causing them to be disabled.
- **Resolution**: Added `source = "answers"` handling to `_resolve_param()` that builds a dict from the keys array, stripping the package prefix from each key.

### Issue 16: qdstart doesn't create parent directories for fpath questions
- **Found in**: Phase 6
- **Repo**: quickdev
- **File(s)**: `qdutils/src/qdutils/qdstart.py`
- **Description**: `_ensure_directory()` only created directories for `dpath` type questions. For `fpath` type questions (like `sqlite_fpath` and `passwordsdb_fpath`), the parent directory (`conf/db/`) was never created, causing SQLite to fail with `OperationalError: unable to open database file`.
- **Resolution**: Extended `_ensure_directory()` to also create the parent directory for `fpath` type questions.

### Issue 17: `sql_to_pdict_table` doesn't handle trailing commas or TIMESTAMP type
- **Found in**: Phase 6
- **Repo**: quickdev
- **File(s)**: `qdbase/src/qdbase/qdsqlite.py`
- **Description**: The schema parser `sql_to_pdict_table()` split column lines on whitespace but didn't strip trailing commas from the type (e.g., `INTEGER,` instead of `INTEGER`). It also only handled `INTEGER` and `TEXT` types, missing `TIMESTAMP`. Additionally, `db_update_columns` didn't pass `db_dict` to the parser, so foreign key references to other tables failed with `KeyError`.
- **Resolution**: (1) Added `.rstrip(',')` to the field_type extraction. (2) Added `TIMESTAMP` type handling as `pdict.TimeStamp`. (3) `db_update_columns` now passes `self.db_dict` to `sql_to_pdict_table`.

### Issue 18: qdstart installs packages in alphabetical order
- **Found in**: Phase 6
- **Repo**: quickdev
- **File(s)**: `qdutils/src/qdutils/qdstart.py`
- **Description**: `configure_applications()` installs packages in the order returned by `get_installable_packages()`, which is alphabetical. When qdforms (which depends on qdrestful) is installed before qdrestful, pip fails with `No matching distribution found for qdrestful`. The package installs successfully when qdstart is re-run (since qdrestful is then already installed).
- **Resolution**: `configure_applications()` now collects failed installs and retries them after all other packages are installed. This handles dependency ordering without requiring dependency graph parsing.
